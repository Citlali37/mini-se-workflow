# 独立评测方案与费用估算

## 预先固定的评测

套件在 `mini_se_workflow/fixtures/evaluation.json`，定义六个需求：待办、文本统计、成绩统计、持久记账、核心规则含歧义、超出支持范围。四个程序任务共有13个独立业务用例；另两个任务预期进入澄清而不生成替代代码。独立用例不交给需求/编码节点，也不参与返工反馈；结束后单独执行，结果写入报告。JSON中保存套件 SHA256、运行编号、错误、独立用例输入输出和服务返回的 token 用量。

状态 `approved` 但独立用例失败仍计评测失败。首次通过率仅以四个程序任务为分母，并要求流程验收及独立验收都通过。成功率以全部六个任务为分母（正确澄清也算该任务成功）。每个需求只运行一次流程，不挑选多次尝试中的成功结果。样本很小，不代表普遍成功率。澄清自动评分只检查确实提出问题且未生成代码，问题质量仍需人工检查。

## 离线结果

`evaluation-fixture.json`：六个固定模拟响应全部通过，四个程序任务三项初稿通过、一项返工后通过。仅说明编排、执行器及评测机制能工作，不能作为模型能力成绩。后续故障注入报告也会明确标注模拟。

## 真实评测前估算（2026-10-13）

模型配置：`deepseek-flash`，思考模式 enabled，沿用本地已配置的接口，不记录密钥。四个程序需求最多各5次节点调用（需求、设计、初稿、两次返工），两个澄清任务各1次，共最多22次逻辑调用。含网络重试总 HTTP 请求上限30；单次 `max_tokens=8192`，单次请求超时60秒（沿用配置）。估算不计后续人工再次运行。

官方价格来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ （本次读取）：Flash 每百万输入未命中缓存高峰2元/空闲1元，输出高峰8元/空闲4元。保守按高峰、无缓存估计。

典型假设：14次请求、每次4000输入和2000输出token，约0.34元。较保守假设：30次请求、每次20000输入和8192输出token，约3.17元。因此本轮预计约0.3–3.2元；这是输入规模假设下的估算，不是保证账单上限。请求上限和输出token上限由客户端执行，达到请求上限即停止。思考token应包含在服务返回输出用量中；费用以服务账单为准。

真实评测输出 `evaluation-real.json`，保留失败与不完整结果；不为了提高分数修改本套件的预期。若发现套件本身错误，必须记录修正原因并变更套件哈希，再作为新实验运行。

## 首轮发现与定向复测（执行前记录）

首轮 evaluation-real.json：3/6成功。待办和记账的需求规格超过每用例8步限制；成绩统计返回无有效正文；文本统计返工一次后通过全部4个独立用例；歧义与超范围均提出问题。保留所有原始失败运行。

修正：提示词明确现有契约中的需求、用例和步骤数量限制；用量记录在解析正文前写入，避免无正文响应的用量遗漏。首轮旧客户端有一个无正文响应未记录usage，因此首轮用量记录不是完整账单。

单独定向复测 todo/grades/ledger（不是重新选取首轮成绩）：仍用同一个固定评测套件，输出 evaluation-followup.json；最多15次逻辑节点调用（3任务×5），含网络重试上限24次HTTP；每次max_tokens提高到16384。按24次×每次20000输入、16384输出、高峰无缓存价格估算约4.11元；典型估算约0.5元。仍为估算，真实金额以用量与账单为准。定向复测与首轮分别报告，不合并声称六项全通过。
