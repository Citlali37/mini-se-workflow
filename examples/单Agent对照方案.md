# 单 Agent / 三 Agent 对照：预注册方案

2026-10-15，真实调用前记录。目标是补充课程答辩证据，不预设三 Agent 更优，不把此小样本结论推广到所有开发任务。

## 实验条件

- 固定套件：`mini_se_workflow/fixtures/comparison.json`，内容哈希随结果保存；三个任务为文本统计、持久记账、图书借阅。
- 每个任务每种方案重复2次，共12个流程。执行顺序交替，第二次重复交换前后，不挑选最佳结果。
- 单 Agent：从原始任务直接生成完整项目；三 Agent：现有需求→设计→编码。单 Agent 复用同一编码协议与质量约束，但在同一次请求内自行分析设计；两者都最多2次代码返工，修复不能随意改变已经确定的文件清单。
- 两者使用同样的公开任务、固定开发用例、执行器、导入白名单、超时和输出限制。三 Agent 的验收执行器使用预先固定开发集，不因其自产用例不同而采用更宽松评分。
- 模型均为本地配置 `deepseek-flash`，thinking=enabled，reasoning_effort=high，请求超时60秒，客户端每次最多尝试3次；本实验整体HTTP请求上限60，每次输出max_tokens=16384。
- 独立用例不提供给任一方案的生成或返工反馈；最后单独执行，开发集与独立集都通过才算该流程成功。图书库公开存储格式，避免用某个实现私有格式作为不公平的隐藏要求。
- 文本统计：开发S1/S4，独立S2/S3；记账：开发L1，独立L2；图书：开发C1/C3，独立其余19项。

## 指标与限制

保存每次运行编号、状态、初稿是否成功、返工次数、实际HTTP请求数、逻辑节点调用数、总耗时、服务返回的输入输出tokens、失败错误、独立结果、源码哈希和实现哈希。失败不从分母中移除。报告不声称统计显著；每任务仅2次重复，未固定服务随机种子，时间顺序、缓存和网络可能影响结果。

三Agent与单Agent的分析组织和上下文不同，不能只归因于“人数”；此实验检验本项目两种完整方案。人工修订图书案例仅用于离线机制测试，不会提供给真实模型或算入模型实验成绩。无正文/超时等请求可能没有完整usage，因此费用记录是可观测部分，不是完整账单保证。

## 执行前费用估算

2026-10-15再次查询官方价格：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ 。Flash高峰无缓存输入2元/百万token、输出8元/百万token；空闲时段1元/4元。首次直接抓取超时，随后官方域名搜索返回完整价格表，采用其当前表格保守计算。

三Agent最多6流程×5节点请求=30次逻辑调用；单Agent最多6流程×3次代码请求=18次，共48次。含网络重试整体HTTP硬上限60。典型按30次请求、每次4000输入/4000输出，约1.2元；保守按60次、每次20000输入/16384输出，约10.27元。输入规模是假设，金额不是硬账单上限；程序硬限制的是请求次数和单次输出token。模型设置对两方案相同。

## 运行方式

在源码目录运行，默认不调用模型：

```powershell
py -3 -X utf8 -m mini_se_workflow.comparison --repeats 1 --output outputs/comparison-fixture.json
```

真实实验（产生费用，按上面预算）：

```powershell
py -3 -X utf8 -m mini_se_workflow.comparison --real --repeats 2 --request-limit 60 --max-tokens 16384 --output examples/comparison-real.json
```

结果与失败会逐流程保存。真实结果未产生前，不填成功率或宣称哪方更优。新增图书质量约束属于公开的补充协议，不以它回写原始8/8记录。
